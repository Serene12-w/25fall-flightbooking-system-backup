# Bug Fixes - 2025-11-12

This update addresses two issues reported in the Passenger UI:

1) Connecting Segment Seat Map opens with "Flight not found for the selected date"
- Root cause: The UI passed the first-segment date for all segments when opening seat maps.
- Fix: PassengerUI now computes per-segment dates (currentSegDates_) by reconciling flight numbers with system flight schedules and reasonable layover windows. The correct date is used for each segment.
- Impact: Seat maps for connecting segments open reliably even when subsequent segments depart next day.

2) Some direct orders displayed as "Connecting"
- Root cause: CSV save format emitted only one trailing comma for non-connecting orders, and loader did not trim whitespace, which could leave stray values and mark orders as connecting.
- Fixes:
  - OrderManager::saveToCSV now writes empty fields for both `connectingFlights` and `connectingSeats` as `,,` for direct orders to keep column count aligned.
  - OrderManager::loadFromCSV trims whitespace and ignores empty tokens when parsing `connectingFlights`.
- Impact: Direct orders consistently show as "Direct"; only orders with actual connecting segments show as "Connecting".

Validation
- Built with MinGW-w64 (WinLibs) static linking via VS Code task / absolute path g++. Build: PASS.
- UI flow:
  - Check-in: Opening seat maps for connecting segments now works (per-segment dates). 
  - Orders list: Direct vs Connecting labels render correctly.

Notes
- If you already have an `orders.csv` produced by previous versions, saving orders after any operation (e.g., a payment) will rewrite rows in the corrected format.
